\# Wazuh Investigation - Failed SSH Authentication



\## 1. Incident Overview



Detection: Failed SSH Authentication



Detection Source: Wazuh SIEM



Wazuh Alert Level: 5



Wazuh Rule ID: 60122



Rule Description : Logon Failure - Unknown user or bad password



Status: Investigated



Environment: Windows 11 SOC Home Lab



\## 2. Investigation Summary



A failed SSH authentication attempt was detected on the Windows 11 endpoint by Wazuh.



The Wazuh agent on the Windows endpoint reported Windows Security Event ID 4625. The event was generated by the Windows OpenSSH server (`sshd.exe`) and was associated with an unknown user name or bad password.



The event was intentionally generated as part of a controlled SOC home lab investigation.

## 6. Analysis

The Wazuh alert was investigated by reviewing the Windows Security log and the OpenSSH Operational log on the affected endpoint.

Windows Security Event ID 4625 confirmed that an authentication attempt failed. The event was associated with the Windows OpenSSH server process (`sshd.exe`).

The OpenSSH Operational log identified the attempted account as `ELCOT` and identified the source IP address as `10.123.151.204`, which corresponds to the Kali Linux VM used in the lab.

The Wazuh alert reported status `0xc000006d` and substatus `0xc000006a`. The substatus indicates that the authentication attempt failed because of an incorrect password.

Only one failed authentication event was observed during this test. Therefore, the available evidence does not establish brute-force activity.

The activity was intentionally generated as part of the SOC home lab and was not an actual unauthorized intrusion.

## 8. MITRE ATT&CK Mapping

### Observed Technique

Technique: T1110 - Brute Force

Sub-technique: T1110.001 - Password Guessing

Reasoning:

The investigation involved a failed SSH authentication attempt caused by an incorrect password. Password guessing is relevant to failed authentication activity; however, only one failed attempt was observed in this investigation.

Therefore, the evidence does not establish a brute-force attack. The technique is documented as a potential ATT&CK mapping for the observed authentication activity rather than as confirmed brute-force behaviour.

## 9. Conclusion

The investigation confirmed that a failed SSH authentication attempt occurred on the Dell Windows 11 endpoint.

Windows Security Event ID 4625 recorded the failed authentication, while the OpenSSH Operational log identified the attempted account as `ELCOT` and the source host as the Kali Linux VM (`10.123.151.204`).

Wazuh successfully collected the Windows event and generated Rule 60122 at Alert Level 5.

The authentication failure was caused by an incorrect password, as indicated by SubStatus `0xc000006a`.

Only one failed authentication attempt was observed. The activity was intentionally generated as part of the SOC home lab, so there is no evidence from this investigation of an actual unauthorized intrusion.

Final Assessment: Controlled lab activity - failed SSH authentication.

## 10. Recommendations

For a production environment, repeated failed SSH authentication attempts should be investigated for possible password-guessing or brute-force activity.

Recommended actions include:

1. Monitor repeated Event ID 4625 authentication failures.
2. Correlate Windows Security events with OpenSSH Operational logs.
3. Investigate the source IP address associated with repeated failures.
4. Review whether the targeted account is legitimate and enabled.
5. Consider additional controls such as strong passwords, account lockout policies, MFA where supported, and restricting SSH access to trusted hosts.
6. Create or tune SIEM detection rules for repeated failed SSH authentication attempts.
